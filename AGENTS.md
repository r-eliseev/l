# AGENTS.md

## О проекте
Репозиторий книг: `books/<slug>/` — независимые книги, у каждой свой контракт
глав, свои источники и своя сборка EPUB. Сейчас их две:

- **ddd-praktika** — «Domain-Driven Design на практике»: 20 глав в 5 частях,
  работающие примеры на Python;
- **eks-course** — «EKS на практике»: 12 модулей по Kubernetes на AWS EKS.

Общие инструменты — в `tools/`, они работают с любой книгой и ничего не знают
ни про одну конкретную. Подробности: `docs/books.md`.

## Команды
У всех инструментов обязателен `--book <slug>`:

- Сборка: `python tools/build_sources_appendix.py --book <slug> && python tools/build_epub.py --book <slug> && python tools/validate_epub.py --book <slug>`
- Тесты: `cd books/<slug>/code && python -m unittest discover -s tests`
- Линтер глав: `python tools/lint_book.py --book <slug>`
- Дословность цитат: `python tools/check_quotes.py --book <slug>`
- Машинные следы в тексте: `python tools/check_ai_tells.py --book <slug>`
- Проверка харнеса (документация, задачи, навыки, опыт): `scripts/check.sh`
- Сигналы устаревания (аудит): `scripts/audit.sh`
- Список навыков: `scripts/list-skills.sh`

## Порядок работы (обязательно)
1. Перед началом прочитай `docs/index.md` и `docs/status.md`, посмотри список навыков (`scripts/list-skills.sh`). Остальное из `docs/` читай по необходимости.
2. Если пользователь назвал задачу (номер или файл в `tasks/`), работай по правилам из `docs/tasks.md`.
3. Для крупной работы без спецификации сначала предложи короткую спецификацию в `docs/specs/` и дождись подтверждения.
4. Реализуй, запусти тесты и линтер.
5. Обнови документацию (см. ниже).
6. Запусти `scripts/check.sh`.
7. Работа не завершена, пока шаги 4–6 не выполнены.

## Когда что обновлять
- Изменил модули, зависимости, потоки данных → `docs/architecture.md`.
- Принял значимое решение (выбор библиотеки, схема данных, компромисс) → новый ADR в `docs/decisions/` по шаблону `_template.md`.
- Изменил поведение фичи → соответствующий файл в `docs/specs/`.
- Закончил работу, не связанную с задачей → файл `docs/log/YYYY-MM-DD-тема.md` и обновление `docs/status.md`. Работа по задаче записывается в «Отчёт» самой задачи.
- Добавил или переименовал файл верхнего уровня в `docs/` → обнови `docs/index.md`.
- Выяснил что-то неочевидное: подход сработал или не сработал, и есть чем это подтвердить → запись в `docs/experience/` (правила: `docs/experience.md`).
- Делал один и тот же многошаговый приём второй раз → предложи навык `skills/<имя>/SKILL.md` (правила: `docs/skills.md`).

## Задачи
- Работай только над задачей, которую назвал пользователь. Сам задачи не выбирай.
- Правила работы с задачами лежат в `docs/tasks.md`. Прочитай их перед началом работы над любой задачей.
- Без одобренного плана код не пиши.

## Навыки и опыт
- Навык — пошаговая инструкция для повторяющейся работы. `scripts/list-skills.sh` показывает имена и описания. Если навык подходит к задаче, прочитай его `SKILL.md` целиком и следуй ему. Остальные навыки не читай.
- Опыт — записи о том, что уже пробовали и что вышло. Перед незнакомой или рискованной работой посмотри `docs/experience/` (тема видна по имени файла) и прочитай записи со статусом «действует».
- Запись в опыт без доказательств не делай. Новые навыки и правки навыков идут отдельным коммитом на ревью человеку.

## Вспомогательные агенты
- Если можешь делегировать часть работы вспомогательным агентам (субагентам), следуй `docs/subagents.md`. Если такой возможности нет, делай сам.

## Аудит
- Периодическая сверка документации с кодом и поиск зависших задач выполняются по просьбе пользователя по правилам из `docs/audit.md`.

## Главные правила

Общие для всех книг:

- Код в главах — только реальный фрагмент пакета `books/<slug>/code/`.
  Линтер проверяет это автоматически; выдуманный код отвергается.
- Новый класс появляется только вместе с главой, которая его показывает,
  и с тестом.
- Цитата — дословная и с номером источника из
  `books/<slug>/src/quotes.json`. Перед коммитом —
  `python tools/check_quotes.py --book <slug> --fix`.
- Проверяемое утверждение (версия, цена, лимит, поведение сервиса) ссылается
  на первоисточник. Навык `proverka-faktov`.
- Глава пишется по контракту из `books/<slug>/src/STYLE.md`: обязательные
  секции в том же порядке, заданное число вопросов, заданное число скрытых
  ответов. Что именно требуется — в `books/<slug>/book.json`.
- Нумерация глав — только в `books/<slug>/src/structure.json`. Файл главы
  без записи в оглавлении в сборку не попадёт.
- Текст — русский, термины в оригинале с переводом при первом упоминании.
- После правок — тесты, линтер, цитаты, пересборка, валидация,
  `scripts/check.sh`.

Для `ddd-praktika`:

- Девять секций в том же порядке, 5–8 вопросов без ответов, 2–4 скрытых
  ответа.
- Объект-значение — `frozen=True`. Изменяемость — ошибка.
- Проверки инвариантов живут в агрегате. Логика в сервисе приложения,
  вызывающая домен, — ошибка (анемичная модель).
- Один домен на всю книгу: подписка на кофе, четыре bounded context'а.
  Свои выдуманные примеры в главах не заводим.

Подробности: `docs/conventions.md`

## Запреты
- Не меняй `books/<slug>/src/structure.json`, `books/<slug>/src/quotes.json`,
  `books/<slug>/src/STYLE.md` и содержимое `books/<slug>/dist/` без явной
  просьбы.
- Не добавляй в `tools/` ветвление «если это книга X»: всё, что нужно знать
  о книге, берётся из её `book.json`.
- Не смешивай книги: примеры, термины и нумерация у каждой свои.
- Не редактируй сгенерированный XHTML в `books/*/.build/` — правь Markdown или
  сборщик и пересобирай.
- Не удаляй и не переписывай существующие ADR. Устаревшее помечай статусом
  «заменено на NNNN» и ссылкой на новое решение.
- Не выдумывай факты в документации, навыках и опыте. Если не знаешь, пиши
  «неизвестно» и добавляй вопрос в `docs/status.md`.
- Не меняй видимость репозитория и не делай его публичным без явной просьбы.
- Не коммить `books/*/.build/` и `books/*/dist/preview/` — они в `.gitignore`.

## Если что-то неясно
Запиши вопрос в `docs/status.md` в раздел «Открытые вопросы» и продолжай с наиболее безопасным допущением, явно его указав. Если вопрос по задаче, пиши его в «Комментарии» задачи (см. `docs/tasks.md`).
