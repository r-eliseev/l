# Архитектура

## Модули

| Путь | За что отвечает |
|---|---|
| `book/src/chapters/` | Исходники глав и приложений (Markdown) |
| `book/src/structure.json` | Оглавление: части, главы, приложения, время чтения. Единственный источник нумерации |
| `book/src/STYLE.md` | Контракт главы: секции, числа вопросов, формат ответа, правила кода и цитат |
| `book/src/quotes.json` | Банк источников: id → url, title, дословные цитаты |
| `book/code/ddd_examples/` | Учебный домен: `shared`, `subscriptions`, `billing`, `strategic`, `anemic` |
| `book/code/tests/` | Тесты пакета (stdlib `unittest`) |
| `book/tools/` | Сборка EPUB, линтер глав, проверка цитат, валидация пакета |
| `book/dist/` | Собранный EPUB и архив с кодом |

## Слои и зависимости

```
главы ──► book/src ──► book/tools ──► book/dist
             │
             └──► book/code (главы цитируют код)

book/src/quotes.json ──► ledger цитат ──► приложение «Источники»
```

Правила зависимостей:

- `book/tools/` и `book/src/` не знают друг о друге: сборщик читает главы,
  линтер проверяет главы по коду, но ни один не импортирует другой.
- `book/code/` не знает о книге: это самостоятельный пакет, который должен
  запускаться и тестироваться без глав.
- `book/src/structure.json` — единственное место, где решено, какие главы
  существуют. Сборщик и линтер берут список оттуда, а не обходят каталог.
- `book/src/quotes.json` — единственное место, где живёт соответствие
  «номер → источник».

Запрещено:

- вводить класс в `book/code/`, на который не ссылается ни одна глава:
  линтер этого не проверяет, но такой класс мёртвый;
- править сгенерированный XHTML в `book/.build/` — источник истины
  Markdown и сборщик.

## Потоки данных

**Сборка книги.** Главы (Markdown) → `build_epub.py` → XHTML-страницы +
`nav.xhtml` + `toc.ncx` + `content.opf` + CSS + обложка → `dist/ddd-praktika.epub`.

**Источники.** `ledger.json` → `build_sources_appendix.py` → `app-d-sources.md`
(приложение «Источники») → сборка. Приложение генерируется механически,
чтобы URL не расходились с ledger.

**Проверка цитат.** Глава → `check_quotes.py` → сравнение каждой
англоязычной цитаты с текстом страницы источника → при несовпадении
привязка чинится автоматически (`--fix`).

**Проверка кода.** Глава → `lint_book.py` → каждый блок `python` ищется в
`book/code/ddd_examples/` → блок, которого нет в пакете, считается
выдуманным и отвергается.

## Внешние системы

- GitHub — приватный репозиторий `r-eliseev/ddd-praktika`, задачи занимаются
  через `origin/main`.
- Ledger цитат Hermes — `%LOCALAPPDATA%/hermes/cache/citations/ledger.json`.
  Вне репозитория, поэтому приложение «Источники» пересобирается, а не
  хранится в git как источник истины.

## Ограничения

- Сборка требует `markdown`, `pygments`, `pillow`. Сам учебный пакет
  работает на чистом стандартной библиотеке Python 3.11+.
- EPUB 3.0: скрытые ответы работают в читалках с поддержкой `<details>`.
  Для старых ридеров оглавление продублировано в NCX.
- Windows: скрипты харнеса рассчитаны на bash и git; в Git Bash работают,
  пути передаются MSYS-формой (`/c/Users/...`).
- `scripts/audit.sh` использует `date -d` (GNU date) — в Git Bash есть,
  в чистом `cmd` нет.
