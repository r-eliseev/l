# Архитектура

## Модули

| Путь | За что отвечает |
|---|---|
| `books/<slug>/book.json` | Паспорт книги: заголовок, автор, обложка, контракт главы, группы источников |
| `books/<slug>/src/chapters/` | Исходники глав и приложений (Markdown) |
| `books/<slug>/src/structure.json` | Оглавление: части, главы, приложения, время чтения. Единственный источник нумерации |
| `books/<slug>/src/STYLE.md` | Контракт главы словами: секции, числа вопросов, формат ответа, правила кода и цитат |
| `books/<slug>/src/quotes.json` | Банк источников: id → url, title, дословные цитаты |
| `books/<slug>/src/evidence-map.json` | Карта «источник → файл с текстом страницы» |
| `books/<slug>/src/evidence/` | Тексты страниц-источников: основа проверки дословности |
| `books/<slug>/code/<package>/` | Пакет с примерами (если у книги есть код) |
| `books/<slug>/code/tests/` | Тесты пакета (stdlib `unittest`) |
| `books/<slug>/dist/` | Собранный EPUB |
| `tools/` | Общие инструменты: сборка EPUB, линтер глав, проверка цитат, линтер машинных следов, валидация |
| `skills/` | Навыки для агентов: инструкции по повторяющейся работе |

## Слои и зависимости

```
книга: books/<slug>/src ──► tools/ ──► books/<slug>/dist
                │
                └──► books/<slug>/code (главы цитируют код)

books/<slug>/src/quotes.json ──► ledger цитат ──► приложение «Источники»
```

Правила зависимостей:

- `tools/` не знает ни про одну конкретную книгу: всё, что нужно знать о
  книге, приходит из её `book.json` и `structure.json`.
- `books/<slug>/code/` не знает о книге: это самостоятельный пакет, который
  должен запускаться и тестироваться без глав.
- `books/<slug>/src/structure.json` — единственное место, где решено, какие
  главы существуют. Сборщик и линтер берут список оттуда, а не обходят каталог.
- `books/<slug>/src/quotes.json` — единственное место, где живёт соответствие
  «номер → источник».

Запрещено:

- вводить класс в `books/<slug>/code/`, на который не ссылается ни одна глава:
  линтер этого не проверяет, но такой класс мёртвый;
- править сгенерированный XHTML в `books/*/.build/` — источник истины
  Markdown и сборщик;
- добавлять в `tools/` ветвление «если это книга X»: непроверяемый код.

## Потоки данных

**Сборка книги.** Главы (Markdown) → `build_epub.py --book <slug>` →
XHTML-страницы + `nav.xhtml` + `toc.ncx` + `content.opf` + CSS + обложка →
`books/<slug>/dist/<slug>.epub`.

**Источники.** `ledger.json` → `build_sources_appendix.py --book <slug>` →
приложение «Источники» → сборка. Приложение генерируется механически,
чтобы URL не расходились с ledger.

**Проверка цитат.** Глава → `check_quotes.py --book <slug>` → сравнение
каждой англоязычной цитаты с текстом страницы источника → при несовпадении
привязка чинится автоматически (`--fix`).

**Проверка кода.** Глава → `lint_book.py --book <slug>` → каждый блок `python`
ищется в `books/<slug>/code/<package>/` → блок, которого нет в пакете,
считается выдуманным и отвергается.

**Проверка текста.** Глава → `check_ai_tells.py --book <slug>` → слова-маркеры
и перекосы форматирования по списку «Wikipedia: Signs of AI writing».

## Внешние системы

- GitHub — публичный репозиторий `r-eliseev/l`, задачи занимаются через
  `origin/main`.
- Внешних зависимостей у сборки нет: банк источников и тексты страниц лежат
  в репозитории, поэтому проверка дословности и сборка приложения
  «Источники» работают одинаково на любой машине и в CI.

## Ограничения

- Сборка требует `markdown`, `pygments`, `pillow`. Учебные пакеты работают на
  чистой стандартной библиотеке Python 3.11+.
- EPUB 3.0: скрытые ответы работают в читалках с поддержкой `<details>`.
  Для старых ридеров оглавление продублировано в NCX.
- CI собирает матрицу книг из каталога `books/`: новая книга попадает в
  проверки сама, без правки workflow.
