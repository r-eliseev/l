## Известные проблемы
- **GitHub Actions не запускается в приватных репозиториях этого аккаунта.**
  Джобы падают за 3 секунды, не получают раннера: ни одного шага не
  выполняется. Проверено пробным workflow из одной строки `echo` — падает так
  же, значит дело не в наших файлах. Публичный репозиторий владельца при этом
  работает (91 успешный прогон, последний — 2026-10-28), приватные падают с
  2026-07-17. Похоже на исчерпание лимита минут Actions для приватных
  репозиториев либо нулевой лимит трат. Лечится в настройках аккаунта:
  Settings → Billing and licensing → Budgets and alerts → Actions. До этого
  проверки надо запускать локально: `bash scripts/check.sh`, `python
  book/tools/lint_book.py`, `python book/tools/check_quotes.py`, `python
  book/tools/build_epub.py && python book/tools/validate_epub.py`.
- `scripts/check-docs.sh` ищет битые ссылки на `.md` по всему репозиторию,
  включая `book/src/chapters/`. Ссылки вида `[1]` внутри глав не считаются
  ссылками (формат не `](...)`), поэтому ложных срабатываний нет.
- `scripts/audit.sh` опирается на GNU `date -d`: в Git Bash работает, в
  чистом `cmd` — нет.
- Приложение «Источники» (`app-d-sources.md`) генерируется из ledger, который
  лежит вне репозитория. На другой машине приложение нужно пересобрать
  (`python book/tools/build_sources_appendix.py`), иначе в нём будут старые
  цитаты. В CI, где ledger недоступен, приложение не пересобирается и
  сохраняется прежним.
- `book/src/quotes.json` — снимок ledger на момент сборки. Новые источники
  в ledger не появятся в книге автоматически.
