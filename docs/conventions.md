# Соглашения

Правила ниже — те, что агенты в этом проекте нарушают чаще всего. Они
общие для всех книг; особенности конкретной книги задаёт её `book.json`
и `src/STYLE.md`.

## Стиль и нейминг

- Текст книг — русский; технические термины остаются в оригинале с
  переводом при первом упоминании («ограниченный контекст (bounded context)»).
- Комментарии в коде — по-русски: они часть учебного материала.
- Имена тестов — по-русски, в форме утверждения: `test_нельзя_отменить_дважды`.
- Строки в Python — 88 символов максимум; длинные вызовы переносить по
  смыслу, а не по ширине.

## Книги

- Книга — каталог `books/<slug>/` с файлом `book.json`. Slug — латиницей,
  строчными буквами, через дефис.
- Нумерация глав — только в `books/<slug>/src/structure.json`.
- Файл главы без записи в `structure.json` в сборку не попадёт: ни линтер,
  ни сборщик об этом не предупреждают.
- Контракт главы задаётся в `book.json`, а не в коде `tools/`. Новый вид
  главы — это новая книга или новый контракт.
- Инструменты в `tools/` общие: не добавляй в них ветвление по названию
  книги.
- Приложения нумеруются буквами: `app-a-…`, `app-b-…`.

## Код примеров

- Пакет `books/<slug>/code/<package>/` — единственный источник правды о коде.
  Код в главах существует только как фрагмент этого пакета.
- Код приводится раньше текста: сначала класс и тест, потом глава.
- Объект-значение — `frozen=True`; изменяемость = ошибка, а не стиль.
- Проверки инвариантов живут в агрегате, а не в сервисе приложения.
- События неизменяемы и несут `occurred_at` (keyword-only — иначе dataclass
  не даёт наследнику добавить обязательные поля).
- Домен не импортирует инфраструктуру: ни БД, ни очередей, ни фреймворков.

## Главы

- Секции — в порядке из `books/<slug>/src/STYLE.md`, без перестановок и
  пропусков.
- «Проверь себя»: 5–8 вопросов (в `book.json` — `questions`), каждый
  заканчивается на «?», без ответов — если контракт не требует иначе.
- «Размышления»: 2–4 вопроса и столько же блоков `<details markdown="1">`.
  Ответ — рассуждение автора, а не «правильный ответ».
- Кодовый блок — до 35 строк; длинное выносить и давать ссылку на файл.
- Номер источника — из `books/<slug>/src/quotes.json`; не больше трёх на
  строку прозы.

## Цитаты и факты

- Дословная цитата — в кавычках-ёлочках, с номером источника сразу после.
- Не больше одной цитаты на абзац; пересказ — своими словами, без номера.
- Проверяемые утверждения (версии, цены, лимиты, поведение сервисов)
  сверяются с первоисточниками: навык `proverka-faktov`.
- Перед добавлением цитаты — `python tools/check_quotes.py --book <slug> --fix`.
- Новый источник добавляется в ledger, а не в `quotes.json` руками:
  приложение «Источники» генерируется из ledger.

## Текст

- Текст проверяется на машинные следы: `python tools/check_ai_tells.py
  --book <slug>`. Замечания — места для взгляда глазами, а не список
  преступлений; пороги правятся в `book.json`, секция `ai_tells`.
- Цитаты из источников не переписываются: они приводятся дословно.

## Тесты

- Что обязательно покрывать: инварианты агрегата, правила объектов-значений
  (неизменяемость, запрет смешивания валют), перевод ACL, восстановление
  состояния из событий.
- Запуск: `cd books/<slug>/code && python -m unittest discover -s tests`.
- Тест без внешних зависимостей: только `unittest`, без pytest и без сети.

## Запреты

- Не править сгенерированные файлы в `books/*/.build/` и `books/*/dist/preview/`.
- Не редактировать `books/<slug>/src/quotes.json` вручную — это снимок ledger.
- Не коммитить `books/*/.build/` и `books/*/dist/preview/` — они в `.gitignore`.
- Не смешивать книги: примеры, термины и нумерация у каждой свои.
