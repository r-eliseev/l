# 0001. EPUB 3 собирается собственным сборщиком

Статус: принято
Дата: 2026-10-28

## Контекст

Книгу нужно собирать в EPUB. Вариантов было три: `pandoc`, `ebooklib` или
собственный сборщик.

- `pandoc` не установлен и в системе, и в требованиях к сборке; его версия
  и набор расширений стали бы скрытой зависимостью от машины.
- `ebooklib` не установлен, а под управляемый им XHTML всё равно пришлось бы
  править руками: `<details>` для скрытых ответов, XHTML-теги, `nav.xhtml`,
  NCX для старых ридеров.
- Своя сборка — это ~400 строк Python, но полный контроль: путь к каждой
  странице, два разных соглашения об относительных путях (`nav.xhtml` живёт
  в `text/`, `toc.ncx` — в корне `OEBPS/`), порядок записей в архиве,
  «mimetype» без сжатия.

Сборщик пишет EPUB 3.0 с `nav`-документом и NCX для совместимости.

## Решение

Собственный сборщик `book/tools/build_epub.py` на стандартной библиотеке плюс
`markdown`, `pygments`, `pillow`.

## Альтернативы

- `pandoc`: отвергнут — внешняя бинарная зависимость, не установлена.
- `ebooklib`: отвергнут — всё равно нужен пост-обработчик XHTML, а лишняя
  зависимость.
- Только EPUB 2 без NCX: отвергнут — часть ридеров без `<details>` показала
  бы ответы сразу.

## Последствия

- Сборка воспроизводима: `python book/tools/build_epub.py` и
  `python book/tools/validate_epub.py`.
- Три внешние зависимости только для сборки; сам учебный пакет работает на
  чистом стандартной библиотеке.
- Скрипты воркшопа требуют `cygpath`-совместимых путей — см. запись опыта
  `docs/experience/2026-10-28-windows-paths-in-harness-scripts.md`.
