# 0003. Один учебный домен на всю книгу

Статус: принято
Дата: 2026-10-28

## Контекст

У книги 20 глав. Если у каждой свой пример, паттерны невозможно сравнить
между собой: глава про агрегат и глава про репозиторий будут говорить о
разных сущностях, и читателю придётся каждый раз переучивать словарь.

Кандидаты на сквозной домен: интернет-магазин, банк, логистика, сервис
подписки на кофе.

Интернет-магазин — слишком знакомый и слишком широкий: в нём легко
затерять различие между bounded context'ами. Банк — перегружен регуляторикой.
Логистика — требует географии.

Сервис подписки на кофе даёт четыре контекста с естественными границами:
подписки, склад, биллинг, legacy-система биллинга. Правила (пауза, отмена,
смена тарифа) — достаточно сложные, чтобы показать инварианты, и достаточно
простые, чтобы не отвлекать.

## Решение

Сквозной домен: сервис подписки на кофе. Четыре bounded context'а:

- «Подписки» (`ddd_examples/subscriptions`) — основной: клиент, тарифы,
  подписка с состояниями;
- «Биллинг» (`ddd_examples/billing`) — Anti-Corruption Layer над чужой
  legacy-моделью;
- «Склад» и «legacy-система» — описаны на карте контекстов
  (`ddd_examples/strategic`), без кода;
- «Анемичная» версия (`ddd_examples/anemic`) — тот же домен без поведения,
  для сравнения в главе 14.

Термины домена: подписка, тариф, уровень, пакет в месяц, пауза, отмена.

## Альтернативы

- Свой пример в каждой главе: отвергнут — паттерны несравнимы.
- Интернет-магазин: отвергнут — слишком широкий, размывает границы.
- Реальный проект владельца: отвергнут — в книге нужен домен, который
  целиком помещается в голове читателя.

## Последствия

- Главы связаны: изменение в `ddd_examples` ломает цитаты в нескольких
  главах сразу, поэтому линтер проверяет код во всех главах.
- Термины домена описаны в приложении А и используются без пояснений.
- Новый класс в пакете допустим только вместе с главой, которая его
  показывает.
