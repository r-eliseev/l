# Приложение А. Глоссарий

*Справочник терминов. Английский термин — первое, что стоит запомнить: на нём
написан оригинал, и по нему вы будете искать материалы.*

## Стратегический дизайн

**Bounded context (ограниченный контекст)** — граница, внутри которой
определена и применима одна модель. Обычно совпадает с подсистемой или с
работой одной команды.[1]

**Ubiquitous language (единый язык)** — язык, структурированный вокруг
доменной модели, на котором говорят все участники команды внутри одного
bounded context.[1]

**Core domain (ядро домена)** — часть домена, дающая конкурентное преимущество;
на неё направлены основные усилия по моделированию.[1]

**Subdomain (поддомен)** — часть домена, выделенная по функциональности.
Microsoft выделяет три категории: core, supporting и generic.[7]

**Context map (карта контекстов)** — описание связей между bounded contexts и
командами через набор паттернов.[13]

**Context map patterns (паттерны карты контекстов)** — девять способов связать
два контекста: Open-host Service, Shared Kernel, Customer/Supplier, Conformist,
Anti-Corruption Layer, Published Language, Separate Ways, Partnership, Big Ball
of Mud.[26]

**Team relationships (отношения команд)** — три типа: Mutually Dependent,
Upstream/Downstream, Free.[26]

**Domain Vision Statement** — документ, описывающий, что за домен и почему
он важен.[1]

**Anti-Corruption Layer (изолирующий слой)** — трансляционный слой между
подсистемами с разной семантикой, не дающий чужой модели проникнуть в домен.[10]

**Shared Kernel (общее ядро)** — явно очерченная часть модели и кода,
разделяемая двумя контекстами; изменения в ней требуют согласования.[26]

**Conformist (конформист)** — downstream принимает модель upstream без
изменений, упрощая интеграцию ценой собственной модели.[26]

**Published Language (опубликованный язык)** — общий документированный язык,
на котором контексты договариваются об обмене.[26]

**Event Storming** — воркшоп-метод Альберто Брандолини: расстановка доменных
событий на временной шкали стикерами.[24]

**Domain Storytelling** — визуальный метод моделирования: сценарии из жизни,
нарисованные и обсуждённые командой.[25]

**Problem space / solution space** — соответственно, область стратегического
анализа и область реализации; core domain — то, что solution space воплощает.[22]

## Тактический дизайн

**Entity (сущность)** — объект, определённый идентичностью, а не
атрибутами; идентичность сохраняется во времени.[1]

**Value object (объект-значение)** — объект без идентичности, определённый
значениями своих атрибутов; неизменяем.[1][27]

**Aggregate (агрегат)** — кластер сущностей и объектов-значений с
оговорёнными границами, внутри которых действуют правила согласованности.[1]

**Aggregate root (корень агрегата)** — единственная сущность в агрегате,
через которую внешний код получает доступ к его содержимому.[1]

**Repository (репозиторий)** — сервис, дающий иллюзию коллекции всех объектов
определённого типа агрегата в памяти.[1]

**Domain event (доменное событие)** — неизменяемая запись о том, что
произошло в домене и что важно для экспертов домена.[1]

**Domain service (доменный сервис)** — отдельный интерфейс для значимого
процесса, который не является естественной обязанностью сущности или
объекта-значения; его имя входит в единый язык.[1]

**Specification (спецификация)** — предикат над моделью, выражающий одно
правило и пригодный для повторного использования.[1]

**Factory (фабрика)** — объект, отвечающий за создание других объектов, когда
конструкция сложна или требует соблюдения инвариантов.[1]

**Module (модуль)** — часть модели, имя которого входит в единый язык.[1]

**Layered Architecture (слоистая архитектура)** — изоляция доменной модели и
бизнес-логики от интерфейса, приложения и инфраструктуры.[1]

**Hexagonal Architecture (гексагональная архитектура)** — приложение с
портами и адаптерами, одинаково управляемое пользователями, программами и
тестами.[23]

## Антипаттерны и смежное

**Anemic Domain Model (анемичная модель)** — объекты-мешки с данными без
поведения, вся логика в сервисах.[3]

**Transaction Script** — стиль, организующий бизнес-логику процедурами, каждая
из которых обрабатывает один запрос.[29]

**Event Sourcing** — хранение всех изменений состояния как последовательности
событий.[28]

**CQRS** — разделение моделей для обновления и для чтения информации.[30]

**Published Language / Conformist** — см. выше, паттерны карты контекстов.

**Ubiquitous language ≠ глоссарий.** Термин означает живую практику: язык,
которым команда говорит постоянно, в том числе в коде.[5]
