# Гайд по стилю и структуре

Книга «Domain-Driven Design на практике» — учебное издание по DDD на русском
языке. Код — на Python (пакет `ddd_examples`), весь код запускается и покрыт
тестами.

## Структура файлов

```
book/
  src/
    STYLE.md          <- этот файл
    quotes.json       <- банк источников: id -> {url, title, quotes[]}
    chapters/
      00-front.md
      01-....md
      ...
  code/
    ddd_examples/     <- пакет с примерами (import ddd_examples...)
    tests/            <- unittest-тесты
  tools/
    build_epub.py     <- сборка EPUB
    lint_book.py      <- проверка глав
  dist/
    *.epub
```

## Формат главы

Каждая глава — один Markdown-файл в `src/chapters/`. Имя файла:
`NN-короткое-имя.md`, где NN — порядковый номер с ведущим нулём.

### Обязательные секции (в этом порядке)

```markdown
# NN. Название главы

*Лист чтения:* 15–20 минут · **Код:** `ddd_examples/subscriptions/model.py`

> **Краткое содержание.** Одно предложение о том, что даёт глава.

## Введение
2–4 абзаца: зачем эта глава, какую проблему решает.

## Основной материал
Подзаголовки ## / ###. Обязательно: определения, примеры из жизни,
таблицы там, где уместно.

## Пример в коде
Код из пакета `ddd_examples` — реальные фрагменты файлов.

## Разбор примера
Пошаговый разбор кода выше: что делает каждая часть и почему именно так.

## Ловушки
2–4 типичные ошибки в этой теме.

## Проверь себя
5–8 вопросов. Короткие. Без ответов.

## Размышления
2–4 вопроса на размышление + **Ответ** (скрыт).

## Что дальше
Мост к следующей главе.

## Источники главы
Список [n] с коротким пояснением, какой именно тезис опирается на источник.
```

### Блок «скрытый ответ»

Внутри секции «Размышления» ответ пишется так:

```markdown
<details>
<summary><strong>Ответ.</strong> Нажмите, чтобы раскрыть</summary>

Текст ответа. Может содержать абзацы, списки, код.

</details>
```

Сборщик превращает это в `<details>` в XHTML. Атрибут `open` не ставить —
ответы должны быть скрыты.

### Блок «врезка»

```markdown
> **Врезка.** Важное уточнение или пример из практики.
```

### Таблицы

Стандартный Markdown. Колонки — короткие.

### Код

```python
from ddd_examples.shared import Money

money = Money.of(490, "RUB")
```

- Язык блока всегда `python`.
- Код должен быть **реальным** — из пакета `ddd_examples` либо точным фрагментом
  реального файла пакета. Не выдумывать API.
- Длина блока — до ~35 строк. Длинное разбивать и давать ссылку на файл.
- Комментарии в коде — по-русски, они часть учебного материала.

### Ссылки на источники

Inline: `[1]`, `[7][8]`. Только id из `src/quotes.json`.
Не больше трёх id на одно предложение.
Прямую цитату источника давать в кавычках и ставить id сразу после неё.

### Стиль

- Обращение на «вы», без снисходительности.
- Русский текст, английские термины — как в оригинале, с переводом при первом
  упоминании: «ограниченный контекст (bounded context)».
- Никаких вводных «в современном мире», «давайте разберёмся».
- Короткие абзацы, 2–5 предложений.
- Примеры — из жизни разработчика, без выдуманных компаний-гигантов.
- Не пересказывать книгу Evans: давать её определения, свои формулировки
  и собственные примеры.

## Соглашения по домену

Единый учебный домен — сервис подписки на кофе:

- **Bounded context «Подписки»** (`ddd_examples.subscriptions`): клиент,
  тарифы `light` / `ritual` / `obsession`, подписка с состояниями
  `active` / `paused` / `cancelled`.
- **Bounded context «Биллинг»** (`ddd_examples.billing`): перевод legacy-модели
  через Anti-Corruption Layer.
- **Анемичная версия** (`ddd_examples.anemic`): тот же домен без поведения —
  для сравнения.

Термины ubiquitous language домена: подписка, тариф, уровень, пакет в месяц,
пауза, отмена, клиент.

Если глава вводит новый класс в домене — он должен существовать в пакете
`ddd_examples`. Нельзя выдумывать несуществующие классы.

## Проверка перед сдачей

```bash
cd code && python -m unittest discover -s tests   # код работает
python tools/lint_book.py                          # структура и ссылки
```

`lint_book.py` проверяет: наличие всех обязательных секций, что id ссылок
есть в `quotes.json`, что `<details>` закрыт, что нет битых путей к файлам
пакета, что в коде нет TODO/FIXME.
