# Написать главу книги

Порядок добавления главы в книгу репозитория. Шаг за шагом, проверка после
каждого. Правила: `docs/conventions.md`.

## Когда применять

- Добавляется глава или переписывается существующая.
- Глава ссылается на новый пример кода — сначала код, потом текст.

Не применять к правке опечаток и перегенерации приложений: там хватит
`python tools/check_quotes.py --book <slug> --fix` и пересборки.

## Шаги

1. **Решить, что в главе.** Одна глава — одна идея, которую читатель должен
   уметь применить. Если две несвязанные — это две главы. Если не помещаются
   упражнения — слишком мелко.

2. **Проверить код.** Если нужен новый пример — сначала класс в
   `books/<slug>/code/<package>/` и тест в `books/<slug>/code/tests/`. Глава
   цитирует только то, что уже есть в пакете: иначе получится выдуманный
   API.
   ```bash
   cd books/<slug>/code && python -m unittest discover -s tests
   ```

3. **Записать главу** в `books/<slug>/src/chapters/NN-имя.md` по контракту
   `books/<slug>/src/STYLE.md`: обязательные секции в том же порядке, лист
   чтения, блок «Краткое содержание», вопросы без ответов, скрытые ответы.
   Источники — только id из `books/<slug>/src/quotes.json`.

   Добавляя главу в книгу, не забудь про оглавление: файл главы и её запись
   в `books/<slug>/src/structure.json` — это одно и то же место в двух
   файлах. Без записи в `structure.json` глава не попадёт ни в сборку, ни в
   оглавление, и линтер этого не заметит.

4. **Проверить факты.** Утверждения о версиях, ценах и поведении сервисов
   сверяются с первоисточниками: навык `proverka-faktov`.

5. **Проверить главу линтером.**
   ```bash
   python tools/lint_book.py --book <slug>
   ```
   Типичные причины ошибок: секция не на своём месте, вопрос не кончается
   на «?», блок кода не найден в пакете, ссылка на несуществующий источник.

6. **Проверить цитаты.** Дословность проверяется отдельно от линтера:
   линтер убеждается, что id разрешается, — цитата проверяется сравнением
   с текстом источника.
   ```bash
   python tools/check_quotes.py --book <slug> --fix
   ```
   `--fix` перепривязывает цитату к правильному номеру, если она дословна
   для другого источника. Если цитата не найдена нигде — переписать её
   по тексту источника, а не подгонять.

7. **Проверить текст на машинные следы.**
   ```bash
   python tools/check_ai_tells.py --book <slug>
   ```
   Замечания — места для взгляда глазами, а не список преступлений. Пороги
   правятся в `books/<slug>/book.json`, секция `ai_tells`. Смысловые признаки
   (ровный ритм, пустые абзацы) линтер не видит: см. навык
   `chelovecheskiy-tekst`.

8. **Пересобрать и провалидировать.**
   ```bash
   python tools/build_sources_appendix.py --book <slug>
   python tools/build_epub.py --book <slug>
   python tools/validate_epub.py --book <slug>
   ```

9. **Проверить харнес и закоммитить.**
   ```bash
   bash scripts/check.sh
   ```

## Как проверить результат

- `lint_book.py` — «Все проверки пройдены».
- `check_quotes.py` — «Все цитаты дословны и привязаны верно».
- `validate_epub.py` — «EPUB валиден», число страниц выросло на одну.
- Глава открывается в браузере: `<details>` закрыт, код подсвечен, таблицы
  не поехали.

## Частые ошибки

- **Текст раньше кода.** Агент описывает API, которого нет, и линтер
  отвергает блок. Сначала класс, потом глава.
- **Глава не внесена в `structure.json`.** Сборка её пропустит молча, и
  читатель не найдёт главу в оглавлении.
- **Цитата с русским пересказом под номером источника.** Проверка цитат
  это ловит: пересказ не совпадает с оригиналом дословно.
- **Блок кода склеен из двух несмежных фрагментов.** Линтер не примет —
  строки должны идти подряд.
- **Вопросы «Проверь себя» с ответами.** Ответы пишутся читателем; в главе
  их быть не должно.
- **Ответ в «Размышления» назван «правильным».** Формулировка должна быть
  «рассуждение автора», иначе читатель ищет единственно верный вариант.
